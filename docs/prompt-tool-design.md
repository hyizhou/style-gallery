# 提示词工具 · 设计记录

> 「术语 → 提示词」翻译层在应用中的设计。当前设计状态描述，不含变更历史。

## 定位

- 目标用户：使用 AI 工具做界面的人——对话助手、编码 Agent、生成式设计工具的使用者。
- 解决三个痛点，各对应一个功能：
  1. **心里有效果，叫不出名字** → 口语别名词典 + 看图认风格（标本卡片本身就是「认」的界面）；
  2. **知道名字，不知道怎么向 AI 描述** → 提示词卡片，一键复制；
  3. **不知道什么效果合适** → 场景导购与搭配推荐。
- 用户旅程：浏览或搜索 → 认出想要的效果 → 进详情页复制提示词 → 粘贴回自己的 AI 工具。本站只负责「翻译」，不生成、不执行。
- 页面是唯一交付物：不做面向 AI Agent 的机器接口（无 llms.txt / JSON 注册表），人看到什么，用户就拿走什么。

## 提示词卡片

- **位置**：由详情页渲染（`StyleDetail` / `LayoutPattern`），置于组件演示区之后——先看效果，后拿措辞。放在页面层而非 DemoKit 内，保证 m3 / antd 官方库页面同样生效。
- **内容三变体**（Tab 切换，默认中文详版）：
  - `short` 一句话版：`用{name}（{en}）风格设计…`，可塞进任意对话开场；
  - `zh` 中文详版：视觉特征（材质 / 光影 / 色彩 / 形状）+ 专业术语 + 1–2 个关键技术词（如 `backdrop-filter`、`grid-template-areas`）；
  - `en` 英文详版：同结构英文。
- **写作规范**：不含「请 / 帮我」等对话词（可拼接性优先）；不写实现代码（那是页面的事，不是提示词的事）；术语中英并置，便于英文命中更稳的工具。
- **形态**：中性代码块样式——等宽字体、行内可选中、右上角复制按钮；**不随 `.theme-<id>` 皮肤变化**，保持「这是一段可复制文本」的直觉，仅随全站明暗主题切换。
- **复制交互**：`navigator.clipboard` 为主、`execCommand` 兜底；成功后按钮文案变为「已复制」约 1.5 秒，配 `aria-live` 提示。

## 口语别名与搜索

- `styles.ts` 每项新增 `aliases: string[]`：3–6 个口语说法。例：玻璃拟态 → 毛玻璃 / 磨砂 / 半透明悬浮 / frosted glass；终端 CRT → 黑客屏 / 绿字黑底 / 命令行界面。
- 主页「视觉风格」网格顶部加搜索框：对 `name / en / aliases / tags` 做包含匹配，过滤卡片；空态给出几个别名示例引导。
- 词典页 `/glossary`：全量词条的平铺列表——术语、别名、一句话解释、迷你预览、进详情的链接。服务两类访问：系统查词，以及「毛玻璃效果叫什么」这类长尾搜索落地；因此**别名必须以页面正文文本出现**（可索引），不能只存在于搜索逻辑里。
- `/glossary` 接入现有预渲染与 sitemap 管线（`seo.ts` 的 pages 列表新增即可）。

## 场景导购

- 数据 `src/data/scenarios.ts`：

```ts
interface Scenario {
  id: string          // 锚点 id，如 ai-product-site
  question: string    // 问题式标题，如「AI 产品官网用什么风格」
  context: string     // 场景约束一两句
  picks: {
    kind: 'style' | 'layout' | 'modal'
    id: string
    reason: string    // 一句话：为什么适合
  }[]
}
```

- 形态：静态内容页 `/scenarios`，每场景一节 + 锚点；每个推荐项链接到对应详情页。**不做交互式问答向导**——与静态站点定位不符，是设计取舍而非实现阶段。
- 场景清单控制在高频真实问题上（5–8 个）：AI 产品官网、个人作品集、中后台管理、活动落地页、内容博客、儿童/趣味产品等。
- 入口：主页 hero 副文案提及；详情页提示词卡片下方回链相关场景。

## 搭配推荐

- 数据 `src/data/pairings.ts`：

```ts
interface Pairing {
  id: string
  name: string            // 如「极光暗夜 × 便当盒」
  styleIds: string[]
  layoutIds: string[]
  why: string             // 这个组合成立的原因
  prompt: { zh: string; en: string }   // 手写的完整合并提示词
}
```

- `prompt` 逐条手写、不机械拼接——组合的取舍与语气是内容价值所在。
- 展示：风格页底部「相配搭配」区，列出包含该风格的 pairing 并链接到搭配对象；布局页同理。搭配提示词复用提示词卡片组件（双变体：中文 / 英文）。

## 数据模型汇总

```ts
// styles.ts —— StyleInfo 扩展
aliases: string[]                     // 必填
prompt: { short: string; zh: string; en: string }   // 必填

// layouts.ts —— LayoutPattern 扩展
aliases?: string[]                    // planned 模式可缺省
prompt?: { short: string; zh: string; en: string }  // ready 模式必填

// 新增独立数据文件
src/data/scenarios.ts
src/data/pairings.ts
```

- 单一数据源：同一份 TS 数据渲染页面正文、搜索索引、sitemap——沿用「数据 → 页面」的既有管线，新风格 / 新模式上线即自动获得词条与提示词入口。
- 提示词文案与 `desc` 分工：`desc` 讲给设计学习者（是什么、从哪来），`prompt` 讲给 AI（长什么样、怎么落地），两者不复用。

## 信息架构与文案

- 主页 hero 主张改为「看到想要的效果，拿到它的名字和提示词」；副文案一句话讲用法（浏览或搜口语词 → 进详情页 → 复制提示词）。
- 顶栏说明文案（「N 种风格 · 可交互组件标本」）同步更新口径。
- 不新增顶栏导航入口：词典与场景从主页与详情页有机进入，顶栏保持克制。

## 边界与非目标

- 不做提示词编辑器 / 参数化生成（站内只读复制）。
- 不做用户系统与收藏后端；分享即 URL。
- 不做面向 AI Agent 的机器可读接口；不以 AI 为第一读者。
- 提示词不承诺跨工具等效（不同模型对同一措辞响应不同），措辞以「特征完整、术语准确」为验收标准。
